# Localization guide

The app is Chinese-first. English copy is keyed by the **Chinese source string** so the
Chinese UI does not need a second key namespace and domain text generated by
`@inferencelab/core` / `@inferencelab/profiles` can be localized at the render boundary.

## API

```tsx
import { useI18n } from '../i18n';

const { t, lt, locale, setLocale } = useI18n();

t('运行实验');                       // UI copy; returns 运行实验 in zh, Run experiment in en
t('另有 {count} 条问题未展开。', { count: 3 });
lt(issue.message);                   // domain copy from core/profiles; exact + template match
```

- `t(source, params)` is for strings written in the component.
- `lt(value)` is for values that come from `@inferencelab/core` or
  `@inferencelab/profiles` (metric labels/reasons, issue messages, plan notes,
  event reasons, preset titles/summaries/tags, evidence notes).
- `src/i18n/zh/domain.ts` holds Chinese overrides for English enums/tokens that
  must stay English in code (for example `WAITING` → `等待`). Use `lt()` at the
  render boundary; do not change the enum values.
- Keep canonical quality tags in English in both locales: `EXACT`, `CALIBRATED`,
  `SYNTHETIC`, `N/A`, `OBSERVED`, `UNKNOWN`, `MEASURED`.
- Keep protocol/technical identifiers as-is: `TP`, `DP`, `EP`, `PP`, `SP`, `PCP`,
  `DCP`, `PD`, `KV`, `HBM`, `TTFT`, `TPOT`, `Token Budget`, `recompute`, etc.
- Do not edit the Chinese source string just to make translation easier unless it
  is an English UI label that should become Chinese in zh mode.
- The English fragment is split by area so parallel work does not conflict:
  `src/i18n/en/{common,header,config,canvas,inspector,lenses,reference,experiments,presets,domain,store,onboarding}.ts`.

## Adding copy

1. Wrap the string with `t(...)` (or `lt(...)` for domain data).
2. Add the Chinese source as a key to the fragment that owns the component.
   Use `{name}` placeholders for interpolation. The same placeholder names must
   appear in the English value.
3. If a dynamic domain message has embedded IDs/numbers, add a template entry
   with placeholders, e.g. `'Rank {rank} 的 KV 池...': 'KV pool for rank {rank}...'`.
4. Run `pnpm --filter @inferencelab/web exec tsc --noEmit` and
   `pnpm --filter @inferencelab/web test`.

## Chinese UI completeness

The Chinese locale must not leak English **chrome**. English is allowed only for:

- canonical quality tags: `EXACT`, `CALIBRATED`, `SYNTHETIC`, `N/A`, `OBSERVED`,
  `UNKNOWN`, `MEASURED`;
- protocol/technical identifiers and units: `TP`, `DP`, `EP`, `CP`, `PP`, `SP`,
  `PCP`, `DCP`, `PD`, `KV`, `HBM`, `DRAM`, `NIC`, `TTFT`, `TPOT`, `P50`, `P95`,
  `Prefill`, `Decode`, `Transfer`, `Engine`, `Rank`, `Token`, `Block`, `Profile`,
  `Plan`, `Run`, `Draft`, `Lens`, `max_num_batched_tokens`, `max_num_seqs`,
  `tok/s`, `GB`/`MB`/`µs`/`ms`, and scenario/model/hardware IDs;
- formulas and code identifiers.

Everything else — panel labels, section headings, status words, legends,
descriptive captions, buttons, tooltips, and empty states — is UI copy and must
be Chinese in zh mode. If a component currently hardcodes an English UI label,
replace it with a Chinese source string wrapped in `t()` and add the English
value to the owning `en/*.ts` fragment.

Their Chinese source strings contain no English prefix; the `What ·` / `Why ·` /

`PREEMPTED`, `BUSY`, `IDLE`, `READY`, `LOADING`) should be rendered through
`lt()`; add their Chinese and English values to the owning fragment. Keep the
underlying enum values unchanged.

## Locale persistence

The locale is stored in `inferencelab.prefs.v1` together with theme and reduced
motion. `?lang=en` / `?lang=zh` override it for a session; the Header language
button persists the choice. `document.documentElement.lang` is updated by the
store and by `App.tsx`.
