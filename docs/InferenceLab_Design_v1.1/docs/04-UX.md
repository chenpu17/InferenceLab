# 04 · WebUI 交互与视觉实施规格（v1.1；覆盖 v1.0 版本）

> **地位：P0 设计合同。** 本文与 `10-UX-STORYBOARDS.md`、`11-UI-ACCEPTANCE.md`、`prototype/inferencelab-ui-reference.html` 共同组成前端交付基线。Agent 不能仅以「高颜值、深色、科技感」为目标自行设计；遇到冲突时，按 00-AGENT-START 中的优先级处理。
>
> **目标：** 让用户在一个工作台里通过操控与观察理解计算、HBM/DRAM、KV Cache、调度、互联、P/D 的真实因果。**动画是仿真事件的投影，而不是另一个独立系统。**

## 1. 体验架构：一个工作台，三种模式，五类观察层

路由首选 `/#/lab`、`/#/experiments`、`/#/reference`。旧文档中的 `/topology` `/memory` `/scheduler` `/transport` `/metrics` 不再是彼此孤立的顶级页面，而是 `/#/lab` 内的 **Observation Lens（观察层）**：`Topology`、`Memory`、`Scheduler`、`Transport`、`Metrics`。任一 Lens 切换都**保留**同一个 ScenarioSnapshot、SelectedEntity、virtualTimeUs、viewport context 和事件过滤条件。

模式位于工作台顶栏：

- **Explore / 原理探索**：预设案例 + 讲解步骤 + 一步一解释；不要求懂参数名。引导抽象到机制。
- **Experiment / 配置实验**：参数 A/B 或单方案编辑 → 校验 → 结构预览 → Run → 回放 → 解释因果；修改配置不篡改旧 Run。
- **Replay / 实测复盘**（M5 完整可用；M0–M3 展示禁用及原因，不做假功能）：导入 Trace → 映射事件 → 观测；无法观察的数据不伪装为真实。

信息层次必须保证「一眼看当前系统、两次点击看原因、三次点击能回到全局」，并不是每个参数都出现在首屏。

## 2. 统一主屏布局（1440×900 设计基准）

```
┌──── 56px Header: 品牌/场景/模式/证据等级 | 实验状态/Run ──────────────────┐
│ 56px Tool Rail │ 292px Config │ 自适应中心 Canvas >= 500px │ 308px Inspector │
│ Lens icons     │ Section tabs │ 上方轻量 KPI（4 个以内）  │ Entity + Why    │
│                │ 条件化控件   │ 拓扑/Block/请求/链路       │ Provenance      │
│                │ Apply/Reset  │ Focus/Breadcrumb/Legend  │ Related Events  │
├────────────────────────────────────────────────────────────────────┤
│ 190–230px Docked Timeline: 事件轨道/时间光标/Run-Pause-Step-Seek/事件详情 │
└────────────────────────────────────────────────────────────────────┘
```

在 1440px 时可折叠左右侧栏以优先保证 Canvas，**不能把核心图缩成小卡片**。右侧 Inspector 默认宽 280–320px，参数侧栏 280–320px；中央视觉空间必须占优。顶部导航不超过 3 个一级功能，观察层在 Rail；避免把 8 个顶级页面做成标签堆叠。

**布局响应**：
- >= 1440px：三栏 + Dock 时间轴，完整交互。
- 1100–1439px：Inspector 默认折叠为抽屉；Canvas 至少 520px。
- 768–1099px：Config / Inspector 为 overlay drawer，Timeline 可缩为 110px 抽屉。
- <768px：可访问实验详情、参数说明及静态概览；**不承诺**在手机小屏完成复杂拓扑编辑，展示明确「建议桌面使用」信息，不允许内容溢出挡住 Run。

## 3. 精确 Design Tokens（可在统一 tokens.css 中维护）

默认暗色主题：

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#080F19` | 页面底层 |
| `--panel` | `#111C2B` | 配置/Inspector |
| `--surface` | `#172539` | 卡片/悬浮条 |
| `--surface-hi` | `#1E3046` | Hover/强调容器 |
| `--border` | `#2A3C51` | 细边界 |
| `--text` | `#E8F0F7` | 正文 |
| `--muted` | `#91A4BA` | 次要描述 |
| `--faint` | `#688098` | 辅助说明（仅大号/非关键） |
| `--compute` | `#68B8FA` | Compute / TP 计算 |
| `--kv` | `#51D6B3` | KV / Cache |
| `--transfer` | `#F5B46B` | DMA / Link / P→D |
| `--wait` | `#A5B3C4` | Queued / Wait |
| `--blocked` | `#F17E89` | OOM / 不可行 / Blocked |
| `--unknown` | `#C19BEB` | 未校准/Unknown |

浅色主题独立定义对比度，不得直接反转暗色。色彩永远辅以 icon、文字或图案，不单凭颜色编码状态。系统字体优先 `Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`，中文回退系统字体；代码/单位使用 `ui-monospace, SFMono-Regular, Menlo, Consolas`。不依赖远程字体/CDN 才能运行。

字号：14px 正文、12px 辅助、11px 高密度标签仅用于非主要信息、20px 小 KPI、24px 主 KPI；行高 1.4–1.6。空白尺度：4/8/12/16/24/32；最常用半径 8/12px，Panel 12px；无大面积渐变、无夸张泛光。画布用低对比 24px 网格；连接线有方向指示且 Hover 显示含义。**禁止默认使用“整屏霓虹科技风”、粒子雨和自动转动的 3D 场景。**

视觉优先级：①选中实体/当前事件 ②可观察的资源约束 ③同一因果链上的关联实体 ④其他背景拓扑。动画色彩只负责强调发生的事件；静态布局保持安静。

## 4. 关键 UI 对象与点击反馈

- **HardwareNode**：默认一块服务器卡片，显卡以 4×4（或随数量响应）阵列显示；节点顶部显示 `Node 0 · 16 NPUs`、容量/忙状态摘要；点击服务器→Inspector Server；点击 NPU→Inspector Device，画布维持全局高亮。双击 Drill-down 到 Device 内部资源/Rank；Breadcrumb 可返回。
- **TP/DP/EP 组**：主画布以半透明边界/连线显示组关系；颜色区别 Group，但必须另有 `Replica 0` 文字和 Line Style；同一物理卡可以属于不同维度组，**不能使用互斥色块假装只属于一种维度**。切换 Lens 时叠加层不同，但设备位置不跳动。
- **KV Block**：内存 Lens 展示池级占用 → 请求级 Block strip → 单块 State；Block 的 `computeState / residency / refs / transferStatus` 分开显示；点击显示 Hash chain、Refs、Event history、Ready 时刻。
- **Link**：显示端点、路径、bandwidth nominal/effective、contentionDomain、direction；点击高亮同域 Link、当前 transfers、waiting requests。
- **Request**：Scheduler Lens 是 Queue / Running / Preempted 三列 + Token Budget ribbon；点击显示 Prefill/Decode/Wait waterfall、所属 cache blocks，支持 `Focus Cause` 回溯到导致阻塞的设备/链路/Block。

Inspector 必须有四区：`What`（是什么）/ `State at time T`（当前状态）/ `Why`（约束或变化原因）/ `Related`（关联实体与事件）。在没有时间预测时，相关字段显示 `N/A · 缺少校准数据`，不能用 0 或臆造数字。

## 5. 参数更改的状态合同（最容易被 Agent 做错）

用户编辑参数立即更新 **Draft**，并调用 `PLAN` 返回结构预览/约束；**永远不更改正在回放的 RunSnapshot**。顶栏显示 `未运行的修改（Draft）`；Run 前可 Restore/Discard；Run 时在 `ExperimentResult` 中冻结 Scenario + ProfilesFingerprint。

`idle → editing → planning → ready/invalid → running → completed → replaying`。`unknown` 是合法的单独状态，不等于 valid。按下 Run 若缺硬件/模型关键字段，显示分级降级选择：`仅结构查看` 或 `使用已标注合成参数进行模拟`（需要用户显式选择）。MVP 不允许完全空白/自动卡死。

参数行至少包含 Label、Value/Unit、Help、Mechanism chips、Support/Quality。不支持的功能呈现 disabled 和 `Why unavailable`，**不得用一个能点的开关替代尚未实现的逻辑**。参数变化时主画布应提示具体变化，如 `Replica 2→4`、`TP Group 16→8`、`可用 HBM +?`；当数值依赖未知时明确 `无法计算`。

## 6. 同一时间轴：虚拟时间与动画时间的绑定

- 所有视图读取相同的 `virtualTimeUs`。Play、Pause、Step Event、Step Scheduler Iteration、Seek、Speed 只修改回放游标/播放速度，绝不重新运行仿真或改变事件因果。
- 一次传输事件 `TransferStarted(t0)` 到 `TransferCompleted(t1)`：橙色流动箭头沿 Link Path 绘制，选择事件时展示 B、link/domain、blockedBy；粒子是**抽象表示**，不是每字节/每 Token。
- 计算事件：设备内部轻微高亮和操作名称，不要让所有卡同时闪烁；实际 busy time 来自事件占用。
- KV 事件：Block 的 reserved/ready/cache/offloading/loading 状态按事件改变；未 Ready 不能通过动画“提前变绿”。
- Scheduler event：Token Budget 扣减、Running/Waiting 队列和 Block 水位在同一 virtualTime 更新；如果暂停，所有 Lens 停在同一时刻。
- 默认 1×，支持 0.25×/1×/4×/16×，保证虚拟时间与屏幕时间可以非线性映射（用于长 idle gaps）；**任何跳过等待段必须提示**。`prefers-reduced-motion` 时以颜色/线型/数字瞬态变化替代移动粒子。
- 多事件密集时先聚合视觉呈现，事件记录保持可追踪；画布上始终只高亮当前实体与其关键关联，不允许 48 请求同时飞满画面。

## 7. 六条必须拍出“分镜”的端到端用例

具体事件帧、焦点和文案见 `10-UX-STORYBOARDS.md`：

1. TP16 DP2 → TP8 DP4：物理卡位置不变、组边界变化、内存预算卡变化、瓶颈解释。
2. GPU HBM 容量 vs KV Pool / Used：双层账本，KV blocks 增加不重复增加 HBM 物理承诺。
3. Prefix Cache 连续命中：两块命中，第三块变更，后续不能跳过。
4. Scheduler budget 8（A6 + B2）：逐 step 展示预算与排队变化。
5. HBM→DRAM→HBM：源/目标占用、Link/DMA busy、load 未完成不能 Ready（M3）。
6. P→D KV 与网络争用：P compute、NIC、Fabric、D HBM、Decode 依赖（M3）。

## 8. 核心页面与内容层级

**Top bar**：当前场景、当前模式、数据质量、实验状态、Run。**Rail**：Lens 导航（保持状态）。**Config**：硬件/模型/部署/内存/调度/负载分类，每次只展开一个组；支持搜索参数（M3）。**Canvas**：单一主视觉，缩放、fit、选中、focus cause、breadcrumb、legend。**Inspector**：对象解释而不只是堆数值。**Bottom**：当前虚拟时间、事件轨道、关联事件、播放/暂停/单步/seek。**Experiments**：Gallery 以“要理解的问题”命名而不是参数简称；第一屏给 3 个精选引导场景。**Reference**：参数百科与版本差异。

**学习引导**：第一进入给 `开始 3 分钟实验` + `打开空白工作台`；引导卡逐步执行「观察 → 调参 → 看到变化 → 找原因 → 总结」，每步可跳过且不遮挡画布；完成后可继续自由探索。

**A/B**：统一标记为 **M3 完整对比功能**。M2 可 `保存当前结果`、手动切换历史运行并展示差异摘要（非 side-by-side 完整比较）；产品首个纵向演示里的 “A/B” 解释为同工况的两次结果切换。M3 实现同步双画布/单轴对照，并明确独立事件时间不同于“同一个事件同时发生”。

## 9. 首屏必需状态与异常

加载、初次空状态、配置非法、关键数据 Unknown、准备模拟、运行中、暂停、完成、事件超量降级、导入失败、Mobile/窄屏、浅色、Reduce Motion、设备溢出、Cache OOM/Preempt 的 UI 反馈均需实现。至少 M1 完成前三类+非法/Unknown；M2 完成 Run/Replay/Perf 降级。示例 `Ascend A3 + GLM-5.3` 标成 `工程模板 · 数据未校准`，禁止展示虚假的准确 TTFT。

## 10. 真实可用与视觉完成度的双重门禁

M0 就必须评审设计 Shell；M1 评审 TP/DP+HBM；M2 评审 Scheduler+KV 动画。每阶段都提交 1440×900 和 1280×800 截图、录屏 30–60s、Playwright 操作证明和用户体验评审清单。任何 UI 不通过，不能仅以 `pnpm test` 通过宣称阶段完成。

完整版量化规则见 `11-UI-ACCEPTANCE.md`。**禁止**：表格/表单占满首屏、全屏 Toast、只靠颜色区分 Group、点击实体只弹 JSON、每个 Lens 重置选择、装饰性假动画、不知道是否 synthetic 的 KPI、频繁微动效抢占视觉注意力。
