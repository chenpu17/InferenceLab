# InferenceLab v1.0 → v1.1 设计审核报告

审核日期：2026-11-05；范围：旧版 README、docs/00–09、四份 Schema、9 个 Example；重点复核产品目标、UI/UX 落地性、Agent 执行收敛性。**本报告是方案审核与原型验证，尚未完成真正的仿真程序。**

## 结论

- v1.0 在技术侧足以开始核心模块开发，但 **不够指导高质量 WebUI 落地**。Agent 若直接执行，容易产出多页表单、拓扑小卡片、性能图表堆叠的普通 Dashboard，缺少用户认知层面的“看因果”。
- v1.1 通过统一工作台、五个 Observation Lens、场景分镜、设计 Token、截图原型和 UX 三门禁，显著降低主观自由发挥空间。**仍不能保证一次性达到理想审美或交互体验**，必须通过 D0/D1/D2/D3 阶段的人眼评审与迭代。
- 技术实现依然要通过固定 vLLM / vLLM-Ascend 版本对照和 Golden Tests；Toy 案例不应冒充真实 GLM-5.3/A3 性能。

## 主要缺陷与修复

| 编号 | v1.0 问题 | v1.1 修订 | 后续风险 |
|---|---|---|---|
| UX-01 | `/topology`、`/memory`、`/scheduler` 等八个独立页面会割裂因果链 | `/lab` 单一主画布 + Lens 叠层，共享 SelectedEntity/time | 需要 Agent 正确设计全局状态 |
| UX-02 | 只有 ASCII 布局，没有具体 Design Tokens、尺寸和视觉参考 | `04-UX` 精确主题色/尺寸/层次 + 原型 HTML + 截图 | 视觉仍需人类审核 |
| UX-03 | 动画要求抽象，没有分镜和状态映射 | `10` 每条用例有“操作→事件→画布→解释→验收” | M3/M4 动画需迭代 |
| UX-04 | UX 验收主要是“3 分钟能操作”，太粗 | `11` 增加 8 项可观察标准、E2E、屏幕截图与人工试用脚本 | 截图测试不能衡量全部认知体验 |
| UX-05 | 只给 Agent 工程入口，缺 UI 评审门禁 | `12` 新增 D0，M0–M3 分阶段 UI 审核 | 不能跳过人工确认 |
| PM-01 | 首个演示要求 A/B，但完整对比排在 M3 | 明确 M2 历史 Run 切换/摘要，M3 完整 Side-by-side | Agent 需区分两种实现 |
| PM-02 | 验收只看 `pnpm test/build`，易造成“能跑但不好看” | 三门禁：正确、可用、视觉质量 | 仍需人看录屏与截图 |

## 已执行检查

- 完整解包 v1.0，阅读其产品、架构、契约、UX、执行、测试、场景说明。
- 新版静态 UI 参考通过 Chromium + Playwright 视觉检查，生成 1440×900 与 1280×800 截图。
- 原型可进行 TP16→TP8，副本数 2→4；点击 NPU 保持 Inspector 关联，切换 Lens 不丢选择；Step 更新示意分镜时钟；浏览器运行未发生 JS page errors。
- 参考原型没有接入仿真引擎，所有演示事件、数字与内存条为显式 **Synthetic / Visual Reference**，不可作为 Core/性能准确性证据。

## 下一次评审应问的五个问题

1. 不读文档的工程师 5 秒内知道系统有多少卡/当前配置/下一步动作吗？
2. 一次“TP16→TP8”的操作后看到的是集团布局变化、HBM 变化与相互作用，还是仅数字变化？
3. 选中一块 KV 能否一路追溯请求、设备、内存和事件？
4. Timeline、Canvas 与 Inspector 在同一时刻是否一致？
5. 禁用能力、未知硬件数据与合成参数是否被诚实提示？

## 发布决策

**推荐 v1.1 用于 AI Coding 开工，前提是先执行 D0 UI 设计冻结，并在 M1、M2 做视觉/交互验收。** 不建议直接把全部 13 份文档一次扔给 Agent，要求它不经评审自主实现 M0–M5。首次任务应仅为 D0 + M0。
